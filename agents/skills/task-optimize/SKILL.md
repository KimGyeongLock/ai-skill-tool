# Task Optimize — 유효한 기준선 이후에만
1. **목표 재확인:** 실제 README 또는 담당자 답변에 근거해 최소/최대화 지표, 계산 방법, 하드 제약, 소프트 목표, 우선순위를 명시한다. 근거 없으면 최적화 대상을 임의로 만들지 않는다.
2. **기준선 저장:** 기존의 동작하는 버전과 산출물을 보존하고 입력, 목표 지표, 제약 위반 건수, 실행 시간, 무작위 시드(필요하면)를 기록한다. 유효하지 않은 해를 기준선으로 비교하지 않는다.
3. **병목 진단:** 데이터 규모/분포와 결과를 읽고 품질 저하의 주요 원인을 찾는다. 타인의 점수나 결과 개수만으로 최적화 방향을 단정하지 않는다.
4. **대안 비교:** 개선 방법 1~2개를 예상 효과, 비용, 실패 위험으로 비교한다. 예: 조합/커버는 Greedy+Local Search, 경로 배치는 제약을 고려한 교환/재배치, 할당 문제는 매칭/정수계획 등. 알고리즘 이름만 보고 적용하지 말고 실제 문제 구조와 실행 조건을 확인한다.
5. **작게 개선:** 가장 효과 높은 한 가지를 구현하고 동일 데이터/동일 측정 조건으로 **개선 전후 비교**한다. 전체 문제에 통하는지와 최소한 작은 입력에서 타당한지도 확인한다.
6. **안전성:** 개선 후 모든 하드 제약을 다시 검사하고, 동률/빈 입력/제한 시간/비결정성 등을 확인한다. 더 나쁜 결과, 제약 위반 또는 불안정하면 기준선으로 돌아간다.
7. **결론:** `지표 | 기준선 | 개선 후 | 증감 | 제약 충족 | 채택 여부` 표와 `[x]/[!]/[?]` 체크를 사용한다. 전/후 동일 입력·실측 근거, 실제 검증 명령, 채택하지 않은 대안과 한계를 간단히 기록한다. 최적성 증명이 없으면 전역 최적이라고 주장하지 않는다.

최적화가 과제 목적이 아니거나 필수 기능을 못 만든 상태라면 성급히 구조를 재작성하지 않는다. 시간 부족 시 **검증된 결과물 보존과 제출**을 우선한다.
