# Task Build
1. **착수:** 앞선 Intake의 공식 근거, 제약, 목적함수, 제출 규격을 다시 확인한다. 같은 세션이면 이미 정리한 내용을 활용하고, 새 세션이면 작업 기록에서 재구성한다.
2. **전체 구조만 먼저:** 모듈 경계, 파일/데이터 흐름, 입출력 인터페이스, 실행 명령을 간결하게 설계한다. 과잉 아키텍처를 피한다.
3. **수직 구현:** 전체 코드를 한 번에 만들지 않는다. 필수 경로(입력 읽기→최소 처리→올바른 출력/실행)를 먼저 완성한다. 이후 핵심 기능을 우선순위별로 추가한다.
4. **검증:** 각 단계에서 최소 1개의 의미 있는 입력으로 실제 동작을 확인하고, 누락/경계/실패 예시를 하나씩 확장한다. 수정한 부분 외 회귀 영향도 확인한다.
5. **기준선 확보:** 제약을 만족하는 첫 결과가 생성되면 이를 보존하고, 목적함수/품질 지표의 **실제 값**, 실행 시간/비용, 제약 위반 여부를 기록한다. 수치를 만들지 않는다.
6. **다음 선택:** 필수 요건 미충족이면 그것부터 해결한다. 충족했으며 최적화 목표가 있다면 `task-optimize`를 사용한다. 그렇지 않으면 `task-verify`를 진행한다.

진행 상황은 `기능 | [x] 완료 / [ ] 진행 / [!] 실패 / [?] 미확인 | 테스트 근거 | 다음 작업` 체크리스트 또는 표로 짧게 보여준다. 구현했다고만 하고 실행 검증을 건너뛰지 않는다. 중요한 AI 제안은 수용/수정/거절 이유를 짧게 남긴다. 과제 외부 전송·Git Push·비인가 권한 변경은 하지 않는다. 단계별 테스트를 생략하고 단번에 전체 구현 완료라고 선언하지 않는다.
