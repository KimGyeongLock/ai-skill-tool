# Task Verify — 근거가 있는 검증

## 절차
1. 구현을 신뢰하기 전에 실제 공식 요구와 완료 기준을 다시 읽는다.
2. **원문 추출:** 각 필수 요구와 입력값을 출처 파일·행·조항 등에 연결한다. 표·숫자가 흐릿하거나 누락되면 추정하지 않는다.
3. **중간값:** 수치·집계·판정의 핵심 입력, 중간 결과, 단위, 분모, 경계와 반올림 규칙을 확인한다.
4. **독립 검산:** 실제 구현과 다른 경로로 기댓값을 검토한다(소규모 수작업 계산, 별도 SQL/스크립트, 불변식·역산 등). 같은 코드의 반복 실행은 독립 검산이 아니다.
5. **실제 실행:** 요구사항별 정상·경계·오류 사례를 테스트한다. 사용한 명령, 입력, 관찰된 결과를 기록한다. 테스트 0건, 전부 skip, 대상 0건이면 통과로 표시하지 않는다.
6. **확정 및 대조:** 필수 요구별 `확인됨 / 실패 / 미확인`을 판정한다. 검산 불가, 애매한 입력, 불일치는 숨기지 않고 수정 우선순위와 함께 보고한다.

## 보고 형식
| 요구사항 | 검증 방법 | 실제 증거 | 상태 |
|---|---|---|---|
| [ID] | [입력·실행 명령 + 독립 검산] | [중간값·관찰된 결과] | 확인됨/실패/미확인 |

마지막에 **제출 차단 문제**, **남은 위험**, **실제로 확인하지 못한 범위**를 적는다.

## 제한
- 실행하지 않은 테스트를 통과했다고 쓰지 않는다.
- 검증을 위한 외부 전송, 허용되지 않은 브라우저 조작이나 설정 변경을 하지 않는다.
- 작은 변경으로 해결 가능한 문제와 시간상 고칠 수 없는 문제를 구분한다.
