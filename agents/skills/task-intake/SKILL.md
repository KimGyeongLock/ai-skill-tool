# Task Intake — 과제 파악

## 목적
문제를 충분히 이해하지 못한 상태에서 코딩을 시작하는 실수를 방지한다.

## 작업 절차
1. 실제 과제 루트, 공식 지시서, README, 관련 입력 파일을 찾는다. 보조 키트의 README와 과제 지시서를 혼동하지 않는다.
2. 공개된 요구를 **필수, 선택, 모호함**으로 나누고 근거 위치를 함께 적는다.
3. 입력, 출력, 파일 형식, 실행 환경, 제출 방법, 오류 처리와 시간 제약을 확인한다.
4. 결과에 영향을 주는 미확정 사항만 최대 3개 질문으로 정리한다. 각 질문은 왜 중요한지와 기본 가정을 구분한다.
5. 실제 제출물의 성공 기준을 테스트 가능한 문장으로 정의한다.
6. 가장 작은 실행 가능한 결과부터 만들 3~5단계 구현 순서와 각 단계의 검증 방법을 제시한다.

## 출력 형식
- 확인한 파일과 근거
- 필수 요구사항 / 선택사항 / 미확정 사항
- 담당자에게 물을 질문 (최대 3개)
- 제출물과 성공 기준
- 최소 구현 순서와 검증 계획

## 제약
- 사용자가 분석만 요청한 단계에는 코드를 수정하거나 설치하지 않는다.
- 근거 없는 기대 동작을 사실처럼 기재하지 않는다.
- 문제가 충분히 명확하면 필요 없는 질문을 만들지 않는다.
- 거대한 파일의 전문이나 원시 데이터를 무작정 채팅에 표시하지 않는다.
