# Task Build — 작은 완성품부터 구현

## 작업 절차
1. 과제의 공식 완료 기준, 기존 스택, 파일 구조와 제공 명령을 확인한다.
2. 필수 기능을 끊김 없이 실행하는 최소 흐름을 먼저 구현한다. 부가 기능은 뒤로 미룬다.
3. 기능 단위로 범위를 좁혀 코드를 변경한다. 기존 인터페이스, 실행 스크립트 및 테스트를 우선 재사용한다.
4. 각 변경 후 실행 가능한 최소 테스트를 수행한다. 테스트 명령, 성공과 실패를 기록한다.
5. 실패가 발생하면 로그와 입력을 바탕으로 원인을 재현해 수정하고 회귀 테스트를 확인한다.
6. 남은 필수 작업, 시간 대비 개선 효과, 검증 공백을 보고한다.

## 가드레일
- 과제 자료와 민감한 내용을 외부 서비스로 전송하지 않는다.
- 요구하지 않은 의존성 설치, 환경 권한 변경, 자동 배포나 Git Push를 하지 않는다.
- 기존 파일을 무작정 대체하거나 템플릿으로 전체 결과물을 덮지 않는다.
- 적용한 외부 공개 코드의 아이디어를 설명할 수 있게 하고, 기존 완성 프로젝트를 통째 대체하지 않는다.
- 필요 이상으로 거대한 아키텍처, 여러 에이전트 또는 도구 설정을 만들지 않는다.

- 실제 확인한 명령과 결과
- 남은 필수 항목과 위험
